# Crew Phase 2 Implementation Plan — manage bots and routines

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Crew the user can create a bot, edit its look / job / persona / model, hide or delete it, and give it routines (scheduled jobs with Run now and run history) — all stored in Hermes exactly as the official Bot Mode client stores them — and can set how many bots may work at once.

**Architecture:** The Crew server gains a management layer: `bots/` (create pipeline, edits, ui_meta compare-and-swap) speaking JSON-RPC through the watcher's existing upstream connection, and `routines/` speaking Hermes REST (`/api/cron/*`) with the token. The browser calls only new `/crew/bots*`, `/crew/routines*` and `/crew/settings` endpoints (plus read-only proxied `/api/model/options` and `/api/sessions/:id/messages`). A small Crew settings file holds the working-bot limit; it rides in the existing `/crew/state` snapshot so every tab updates.

**Tech Stack:** as Phase 1 (Node 24, TypeScript strict ESM, npm workspaces; Hono, ws, Zod, Vitest; Vite, React 19, Tailwind v4, shadcn/ui, TanStack Query; @playwright/test). New server deps: `cron-parser@^5`, `luxon@^3` (+ `@types/luxon` dev). Hermes v0.23.0 @ `2bd378ed1b8d6bf2192cb26e0a55ff3091e6bd19`.

**Spec:** `docs/superpowers/specs/2026-11-08-crew-app-design.md` (§2 goals 5–6, 9; §4 anti-goals; §6.1 mapping; §6.6 budget; §7 right panel + New bot dialog; §9 Phase 2 acceptance). **Protocol facts (binding):** `docs/phase2/hermes-facts.md` — every Hermes call below cites its section there (`F§n`). Phase 1 evidence: `docs/phase1/`.

## Global Constraints

- Everything in the Phase 0 and Phase 1 Global Constraints still holds (loopback-only, Host/Origin/CSRF/cookie guards on every mutating request, token never reaches the browser or logs, Zod at boundaries, no `console.log`, files < 400 lines, functions < 50 lines, conventional commits, TDD). Branch: **`crew-phase2`** from `crew-phase1`.
- **Work happens inside the VM** (`/home/ali/projects/grok-bots`). Tests: `cd app && npm test -w server`, `npm test -w web`. Deploy: `cd app && npm run build -w web && npm run build -w server && systemctl --user restart crew`. Live e2e: `cd app/e2e && npx playwright test`. Never restart `hermes-gateway` / `hermes-dashboard` or edit `~/.hermes` config.
- **Parity with the official Bot Mode client** (`F§5`): bots are created with RPC `profiles.create` (never REST `POST /api/profiles`); look lives in `ui_meta['hermes-bots']`; avatar via `profiles.set_asset`; the chat is a hidden session titled exactly **`Bot Chat`**; routines live in the bot's own cron store, named **`[bot:<profile>] <title>`**.
- **ui_meta is written only by read-modify-write of the whole `hermes-bots` object with CAS** (`profiles.configure {name, ui_meta:{'hermes-bots': next}, ui_meta_expected_revisions:{'hermes-bots': rev}}`), up to **3** attempts; a conflict is a *successful* reply with `applied.ui_meta_conflicts` (`F§3`). Keep every unknown key; drop `chat`; never send `image` or `pet`. Never touch the top-level `hermes-bots-groups` key.
- Writes to `profile.yaml` are **sequential, never parallel** (description races ui_meta, `F` Gotcha 16). SOUL / description / model have no revision: send only dirty fields and refuse to overwrite a value that changed since the form loaded (baseline check, `F§6`).
- Names: `^[a-z0-9][a-z0-9_-]{0,63}$`, reserved **`hermes, default, test, tmp, root, sudo`**; `default` can be neither created nor deleted (`F§1.1`).
- No intro "Hey, tell me about yourself!" turn after creating a bot (costs a model call; `F§1.2` step 9) — the user says hello when ready.
- Routine prompt = the user's plain instruction (the job runs in the bot's own store; no `hermes -p` wrapper, `F` Gotcha 8). Delivery default **run history only** (`deliver: 'local'`); "also post in the chat" = `deliver: 'bot-chat'` (one extra turn per run, §6.6). One-shot delays are sent as **`in <n><unit>`**, never a bare duration (`F§4.4`).
- Working-bot limit: setting `maxWorkingBots` — integer **1–20** or **`null` = no limit**; default **2** (spec §6.6); enforced in the composer as in Phase 1.
- Avatar images: PNG/JPEG/WebP data URLs, ≤ **2,000,000** decoded bytes; the browser downscales any picked image (png/jpeg/webp/gif ≤ 15 MB) to a **256 px PNG** first (`F§2`). Crew's shape picker offers **`circle`** and **`squircle`** (both in Hermes's vocabulary; Crew already renders them).

## Review Focus

1. **A bot edited in the official Webapp while Crew's Profile form is open** → saving in Crew keeps the Webapp's change (no lost title / groups / pinned / sections; a changed persona is not silently overwritten). Tests: Task 2 `keeps a concurrent writer's keys after a conflict`, Task 4 `refuses to overwrite a soul changed since load`, Task 11 `concurrent edits keep both changes`.
2. **Awkward names** — Korean or accented names, a taken handle, a reserved word → the handle preview matches what Hermes will accept, the error is plain, nothing half-made is left behind. Tests: Task 2 `slugifies like the official client`, Task 3 `maps an existing profile to name_taken without further calls`, Task 7 `shows the server's handle error inline`.
3. **Run now on a routine that runs for many minutes, or is already running** → the button shows "Running…", no request hangs or times out in the UI, a second press says "Already running". Tests: Task 5 `run now returns started while the trigger is still pending`, `run now reports already_running on 409`; Task 9 `run now shows already running`.
4. **Schedules near edges** — a time in the past, a DST change, an invalid custom cron, a prompt Hermes's scanner rejects → plain message under the form, nothing saved. Tests: Task 5 `preview handles a DST transition`, `rejects a once_at in the past`, `surfaces Hermes's rejection message`; Task 9 `shows the server's rejection under the form`.
5. **Deleting a bot whose chat or panel is open** → Crew leaves the bot's page, the roster drops it within seconds, no error screen; the primary bot offers no Delete. Tests: Task 4 `refuses to delete the primary bot`, Task 8 `delete requires the typed handle and goes home`.
