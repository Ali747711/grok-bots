# Crew Phase 0 Implementation Plan (+ Phase 1 outline)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the Crew server's secure boundary in front of Hermes (127.0.0.1:9120), identify the live Hermes protocol, and prove (or disprove) that a headless watcher receives approval requests for turns it didn't start — the gate for Phase 1.

**Architecture:** A Node 24 + Hono server on 127.0.0.1:7070 with its own login (one-use launch link → HMAC-signed cookie), Host/Origin/CSRF guards, an allowlisted REST proxy and a WebSocket proxy to Hermes that inject the Hermes token server-side. Hermes's dependency-free shared protocol client (`apps/shared/src`) is vendored from a pinned commit and drives a protocol probe and a headless approval watcher.

**Tech Stack:** Node 24, TypeScript (strict, ESM), npm workspaces, Hono + @hono/node-server, `ws`, Zod, Vitest. Hermes Agent v0.23.0 @ `2bd378ed1b8d6bf2192cb26e0a55ff3091e6bd19`.

**Spec:** `~/projects/grok-bots/docs/superpowers/specs/2026-11-08-crew-app-design.md` (VM) — §6.2 boundary, §6.3 protocol, §6.4 approvals, §8 Phase 0, §9 acceptance. Hermes API map: `~/projects/grok-bots/research/hermes-api-map.md` (legacy shapes may be superseded by the probe).

## Global Constraints

- **Where code lives:** git repo at VM `~/projects/grok-bots` (root; code under `app/`, docs under `docs/`; `vendor/` and `research/*.txt` ignored). Edit in a Mac clone at `/Users/mac/projects/grok-bots` (remote `vm` = `ali@192.168.64.16:projects/grok-bots`, VM repo has `receive.denyCurrentBranch=updateInstead`); `git push vm main` then run every command in the VM: `ssh ali@192.168.64.16 'cd ~/projects/grok-bots/app && <cmd>'`.
- Node 24 (`/usr/bin/node`), npm, TypeScript `strict: true`, `"type": "module"`, NodeNext resolution.
- Crew listens on **127.0.0.1:7070** only. Hermes upstream **http://127.0.0.1:9120**.
- Allowed `Host`: exactly `127.0.0.1:7070`, `localhost:7070`. Allowed `Origin`: exactly `http://127.0.0.1:7070`, `http://localhost:7070`. Missing or `null` Origin is rejected wherever Origin is required.
- State dir `~/.config/crew` (mode 0700); `admin-secret` and `cookie-secret` files (32 random bytes, mode 0600).
- Cookies: `crew_session` — HttpOnly, SameSite=Strict, Path=/, Max-Age=7776000 (90 days), value = HMAC-SHA256-signed `{sid, exp}`; `crew_csrf` — SameSite=Strict, Path=/, not HttpOnly, random 32 bytes base64url. Mutating requests send header `X-Crew-CSRF` equal to the cookie.
- Launch tickets: 32 random bytes base64url, single use, TTL 60 s. Launch URL format: `http://127.0.0.1:7070/login#ticket=<ticket>`.
- Hermes token: read from `~/.hermes/webapp/session-token`; sent upstream as `X-Hermes-Session-Token` (REST) and `?token=` (WS). **Never** sent to the browser, never logged.
- REST proxy allowlist (prefix match): `/api/profiles`, `/api/sessions`, `/api/cron`, `/api/skills`, `/api/analytics`, `/api/model`, `/api/chat/file-upload`, `/api/chat/image-upload`, `/api/status`. Everything else → 404 `{"error":"not_proxied"}`.
- No `console.log` in production code: use `server/src/log.ts` (JSON lines to stderr). Validate env/config and request bodies with Zod. Files < 400 lines, functions < 50 lines, no mutation of shared objects.
- Tests: Vitest, run with `npm test -w server`; coverage target 80% for `server/src`. Live-LLM steps use the default model (Haiku 5.5) and only the fixture prompts below — the OpenRouter key has a $2 limit.
- Commits: conventional (`feat:`, `test:`, `chore:`, `docs:`), one per task minimum, in the VM repo.

## Review Focus

1. **Hermes gateway restarts while Crew runs** → open browser sockets get a clean close (code 1012) instead of hanging; the watcher reconnects and re-subscribes. Tests: Task 5 `upstream drop closes client with 1012`, Task 9 `resubscribes after reconnect`.
2. **Token rotated by Webapp sign-out mid-session** → REST answers 503 `hermes_signed_out` after one re-read; WS closes 4401. Tests: Task 4 `401 twice → 503`, Task 5 `upstream 4401 → client 4401 + token refresh`.
3. **Large upload through the REST proxy** → body streamed through intact, not buffered/truncated. Test: Task 4 `forwards a 5 MB body byte-identical`.
4. **Same user on `localhost:7070` and `127.0.0.1:7070`** → both hosts serve login and work after their own login. Test: Task 3 `both allowed origins pass`.
5. **Double-click on the launch link / replayed ticket** → exactly one redemption succeeds. Test: Task 2 `concurrent redeem yields one success`.

Also pinned: the Hermes token never appears in logs (Task 4 `logs never contain token`).
