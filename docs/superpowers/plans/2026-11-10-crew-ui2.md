# Crew UI 2 (crew-bots reskin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Crew looks and feels like the user's crew-bots design (tokens, primitives, motion, three floating panels, tabbed profile) in dark and a new light theme, keeps every Crew feature and safety rule, and makes approvals, skills (toolsets) and screen sleep real Hermes settings.

**Architecture:**
- Server first: three small additions behind the existing bot routes. Cosmetics (`pinned`, `role`, avatar accessories, plus `job` on `BotView`) ride the `ui_meta['hermes-bots']` CAS write. Approvals, toolsets and sleep are sparse `PUT /api/config?profile=` writes under the bot lock. The primary bot is refused with `primary_not_supported`.
- Web: the crew-bots token set and primitives are copied into `app/web` (never imported) and reformatted to Crew's style. Then each screen is restyled over Crew's existing data layer, routes and tests.
- The URL stays the source of truth (`?panel=computer|routines|profile|group`, plus `&tab=` for profile tabs). One chat session per selected bot is lifted above the work area, so the profile and the side panel share it.

**Tech Stack:** Server: Node 24, Hono, Zod 4, Vitest. Web: React 19.2, Vite 8, Tailwind v4, TypeScript ^7, `@base-ui/react` ^1.9 with shadcn `base-luma`, `motion` ^14.11.1, `@fontsource-variable/inter` ^5.3.0, react-router-dom 7, lucide-react, sonner, @novnc/novnc, bot-avatars 0.2.2, Vitest + Testing Library. e2e: Playwright against the deployed Crew (127.0.0.1:7070) and live Hermes (127.0.0.1:9120).

**Spec:** `docs/superpowers/specs/2026-11-10-crew-ui2-reskin-design.md` (§11's 21 calls are decided). Facts: `docs/ui2/hermes-facts.md` ("Q1"–"Q8"). File map: `docs/ui2/study.md`. Shorthands: `CB/` = `crew-bots/client/src/`, `CW/` = `app/web/src/`, `CS/` = `app/server/src/`.

## Review Focus

1. **Window shortcuts while typing into the bot's screen.** With focus inside `[data-testid=live-view]`, or while the user holds control, `d`, `/`, `⌥1`–`⌥9`, `⌘K`, `⌘\` and `Esc` must do nothing. `⌥2` would switch bots and hand control back mid-task. Tests: Task 5 `ignores shortcuts from inside the live view and while control is held`; Task 7 `⌥digit and ⌘K do nothing from inside the live view or a field`.
2. **Browser storage that throws or is empty** (private window, blocked site data). The app must render with the defaults: theme `system`, side panel closed, no crash. Tests: Task 4 `falls back to system when localStorage throws on read and write`; Task 6 `starts closed and never throws when storage is blocked`.
3. **A toolset that Hermes's own Toolsets tab turned off** (in `platform_toolsets.cli`, not `agent.disabled_toolsets`), and a stale sandbox marker. Expected: "on" really turns it on, and a later sandbox-off never strips the user's own `browser` entry. Tests: Task 3 `turns on a toolset still off after the list write through Hermes's toolset route`, `a user's browser write clears a stale addedBrowserDisable`, `browser turned off by the user survives sandbox on and off`.
4. **Unpin against a Webapp copy that still says pinned, and odd stored values.** Expected: unpin writes `pinned: false` (key present); only boolean `true` reads as pinned (`'true'` and `1` do not). Tests: Task 1 `unpin writes pinned false and never deletes the key`, `reads pinned only from boolean true`.
5. **Leaving the profile with unsaved edits** (Esc, Back, the rail, `⌥digit`). Expected: the edits are still there on return to that bot, and never shown on another bot. Test: Task 13 `keeps unsaved edits per bot across leaving the profile`.

## Plan rulings

- **R1. Where Crew remembers the user's own toolset choice.** It uses the existing sandbox marker `ui_meta['hermes-bots'].sandbox.addedBrowserDisable`, with no new storage.
  - A `browser` entry in `agent.disabled_toolsets` that Crew did not add is the user's, and sandbox-off never strips it (today's `offPatch`).
  - While the sandbox state is not `off`, `browser` cannot be toggled (409 `toolset_locked`), so the marker cannot go stale through Crew.
  - Any Crew toolsets write of `browser` sets `addedBrowserDisable: false` when it was true. The user now owns the entry.
  - Other toolsets are never touched by sandbox on/off, because both patches rewrite the whole list and keep other names.
- **R2. Approvals.**
  - The raw `approvals.mode` normalizes as: absent → `smart` with `isDefault: true`; YAML `false` → `off`; `true` → `manual`; `manual|smart|off` matched case-insensitively and trimmed; any other string → `manual` (Hermes does the same, Q4).
  - Writes are always the string `{approvals: {mode}}`. Writing on first change makes rooms (unset → manual) and chats agree.
  - `sandboxed` = `sandboxStateOf(raw).state === 'on'`. That is the only case where Q5's note is shown.
- **R3. Sleep.**
  - `GET …/screen/config` keeps returning the raw `idleStopMinutes: number | null`.
  - The UI shows 60 as "1 hour" and 0 as "Never". Anything else shows "15 min", because Crew writes 15 at the next start.
  - Crew only ever writes 15, 60 or 0.
- **R4. Side-panel memory** is `localStorage['crew-side-panel']`, one of `computer | routines | none`, read and written in try/catch.
  - It is written only by user actions: the header buttons, the side panel's tabs, `Close panel` and `⌘\`. Loading a URL never writes it.
  - A rail click from a bot page keeps that page's `panel` (none, side panel or profile).
  - A rail click from anywhere else, and the home redirect, use the remembered choice.
  - Needs-you links are plain links to `/bots/<name>` with no panel, because they are not the rail.
  - After a delete Crew navigates to `/`, so the home redirect applies the remembered choice. A fresh context has nothing stored, so the e2e URL assertions (`/bots/crew-test$`, `/bots/default$`) hold.
- **R5. Rail membership**, in order of precedence:
  1. primary → Pinned, always first, with a "Primary" tag;
  2. status `needs_you` (only while statuses show, i.e. not stale) → Needs you;
  3. hidden → Hidden (n);
  4. `pinned` → Pinned;
  5. otherwise → Crew.
- **R6. Profile tabs** live in `?tab=identity|avatar|soul|skills|apps|advanced`. Identity is the default, and an unknown value means identity. Leaving the profile drops both `panel` and `tab`.
- **R7. Shortcut guard.** `shouldIgnoreShortcut(event)` is true when:
  - the target is editable (`input, textarea, select`, contentEditable);
  - the target or `document.activeElement` is inside `[data-testid="live-view"]`;
  - `liveControlHeld()` is true;
  - or `event.defaultPrevented`.
  `Esc` is also ignored while focus is inside `[role=dialog], [role=alertdialog], [role=menu], [role=listbox]`. `⌘↵` is not a window shortcut: the profile root handles it on `keydown`, so it works inside fields.
- **R8. Unsaved profile edits** (`FormSync`) are kept per bot in memory for the life of the tab, in the draft store beside composer drafts. On return they are applied through `mergeFresh`. They are never written to storage.
- **R9. Needs-you entries.** Each one is a request card. Its header row is a `Link` to the chat that holds kind, age, the summary and "Open chat", so the link text contains the summary. The answer buttons sit below the link, outside it.
- **R10. Run card copy.**
  - Running: the running step's summary (`BlurSwap`), "Working · n step(s)" and an `IndeterminateBar`.
  - Done: "Worked for Ns · n step(s)", or "Worked · n step(s)" with no duration.
  - Interrupted: "Stopped after n step(s)".
  - A failed step shows "Failed". Details keep "Show more" past 4000 characters.
- **R11. Link chip copy** (`linkChip(kind, link, control)`):
  - kind `loading|starting` → "Connecting…"; `off|missing|low_memory|error` → "Off";
  - kind `live` with link `idle|connecting` → "Connecting…", `reconnecting` → "Reconnecting…", `failed` → "Not connected";
  - link `live` → "You're in control" (watermelon dot), "Someone is in control", or "Live" (watermelon dot).
  - It is the only element on the page with the text "You're in control". `ControlBar` loses its badge.
- **R12. Soul starters** "Careful", "Fast" and "Friendly" use crew-bots' texts with `<title>`. A click appends the text after a blank line. They never replace text.
- **R13. Contrast.** Beyond the spec's rule, the check also requires:
  - `--destructive` ≥ 4.5:1 on shell and raised (error text);
  - `--primary-foreground` on `--primary` ≥ 4.5:1 (button text).
  The focus ring is `ring-ring` at full opacity: the check compares `--ring` itself, and no `ring-ring/<n>` remains in `CW/`. Only light values may move to pass. In dark, only `--muted-foreground` and `--ring` may change, each by the smallest step that passes (spec §5.1 ruling).
- **R14. One avatar component.** crew-bots' `BotAvatar` is merged into Crew's `CrewAvatar`, which keeps photos, colour, `shading="fabric"` and the sleep rule. It gains a corner `StatusDot` (Task 7) and accessories for shape avatars (Task 14).
