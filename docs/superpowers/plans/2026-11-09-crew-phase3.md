# Crew Phase 3, bot computer: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring each Hermes bot's own desktop into Crew:
- a live view;
- take control / hand back;
- a header thumbnail;
- stop;
- a use-screen switch;
- a 15-minute idle stop.

**Architecture:**
- **Server:** Crew's server adds a guarded `/api/display/ws` raw splice to Hermes (no token, no Origin), a fail-closed `display.*` guard on the existing `/api/ws` proxy, and screen routes. The routes write sparse per-bot Hermes config (idle stop, use-screen) and start screens.
- **Web:** noVNC 1.7.0 on the shared JSON-RPC socket. A Computer tab and header thumbnail, built from `display.status` plus events filtered by profile.

**Tech Stack:** Node 24, Hono, `ws`, Zod, Vitest (server); React 19, Vite 8, Tailwind v4, shadcn base-nova, `@novnc/novnc` 1.7.0, Vitest + Testing Library (web); Playwright live e2e in the VM.

**Spec:** `docs/superpowers/specs/2026-11-09-crew-phase3-bot-computer-design.md`. **§11 overrides earlier sections.** The facts are in `docs/phase3/hermes-facts.md`.

## Global Constraints

- Every `display.*` call carries `profile`: in the web client, enforced by the server guard (spec §4 anti-goal 2, §11 R7).
- No CSP change, no new TCP port, and the token and tickets are never logged or shown (spec §4, §7).
- Hermes config writes are sparse `PUT /api/config?profile=<bot>` bodies. Never PUT a GET result (§11 R1).
- Close-code mapping per spec §5.1 (server) and §11 R3 (browser). A dropped link keeps control; closing the Computer tab hands back; moving to or from Expand keeps control (§11 C1).
- Xvnc hygiene: dial only after 300 ms mounted; at most 3 dials per bot per 10 s per page (§11 R4).
- `@novnc/novnc` is pinned at exactly `1.7.0`. Vite `build.target` allows top-level await (es2022).
- UI-rebuild rules still apply:
  - tokens only (the scan test);
  - the dark-trap rule (no un-prefixed `bg-`/`border-` overrides on shadcn variants with `dark:` classes);
  - files under 400 lines, functions under 50, no `console.log`;
  - conventional commits;
  - the 16 existing live e2e specs keep passing.
- Live probes and e2e touch only `crew-test` and `e2e<digits>` bots, never `default` / `reese` / `x` screens or config. Don't restart hermes services or edit `~/.hermes` files directly; the sanctioned path is Hermes REST through Crew.
- Never push.

## Review Focus

1. **The browser link drops (lid closed, Wi-Fi) while the user holds control** → Hermes keeps the human lease (no silent hand-back). Test: Task 2 `turns an abnormal browser close into an upstream terminate, keeping the lease`.
2. **The user opens Expand during a take-over, then closes it** → control stays with the user throughout; only leaving the Computer tab hands back. Test: Task 5 `keeps control when the view moves between the panel and Expand`.
3. **A crafted frame on `/api/ws`** (no profile, a whitespace-padded profile, NaN, an array batch, a binary frame, `display.start`) → never reaches Hermes; the browser gets a JSON-RPC error. Test: Task 3 `refuses display frames Hermes would mis-target`.
4. **Fast switching between bots, tabs or Expand** → no burst of aborted VNC dials. Xvnc never locks viewers out. Test: Task 4 `limits dials to three per bot per ten seconds and waits 300 ms after mount`.
5. **A forgotten background tab** → the screen still idle-stops; the view detaches after 5 minutes hidden. Test: Task 5 `detaches after five hidden minutes and re-attaches when visible`.

### Task 1: Screen config and start routes (server)

**Files:**
- Create: `app/server/src/bots/screen-config.ts`, `app/server/src/http/screen-routes.ts`
- Modify: `app/server/src/app.ts` (mount the routes); the REST helper if needed
- Test: `app/server/test/screen-config.test.ts`, `app/server/test/screen-routes.test.ts`

**Interfaces:**
- Consumes: the existing Hermes REST client used by `rest-proxy.ts` / `bots/*` (token-bearing server fetch); `withBotLock(name, run)` from `bots/bot-lock.ts`; `PROFILE_NAME_RE` from `bots/names.ts`; the server's gateway RPC client used by the bot routes.
- Produces:
  - `readScreenConfig(deps, name): Promise<{ idleStopMinutes: number | null; headed: boolean; autoStart: boolean }>` (GET `/api/config?profile=`, keeps only these keys);
  - `ensureIdleStop(deps, name, minutes = 15): Promise<void>` (sparse PUT only when different);
  - `setUseScreen(deps, name, on: boolean): Promise<void>` (one sparse PUT `{config:{browser:{headed:on}, bot_desktop:{auto_start:on}}}`, then `ensureIdleStop`).
- Routes:
  - `POST /crew/bots/:name/screen/start` → 200 `display.status` result. 502 `{error:'screen_config_failed'}` if the idle write fails, and then no start.
  - `GET /crew/bots/:name/screen/config` → `{ useScreen, idleStopMinutes }`.
  - `PUT /crew/bots/:name/screen/config` with body `{ useScreen: boolean }` (Zod, strict) → `{ useScreen, idleStopMinutes }`. It returns 400 for `default` (§11 R8).
- Names: `PROFILE_NAME_RE` and a known bot, else 404. The lock is held around config writes only, not around `display.start`.

### Task 2: Display socket proxy (server)

**Files:**
- Create: `app/server/src/hermes/display-proxy.ts`
- Modify: `app/server/src/hermes/ws-proxy.ts` (route `/api/display/ws` to the new module behind the same `isAllowedUpgrade`)
- Test: `app/server/test/display-proxy.test.ts`

**Interfaces:**
- Produces `attachDisplayBridge(client: WebSocket, req: IncomingMessage, deps)`, called from the shared upgrade handler for `/api/display/ws`.
- Upstream: `ws://<hermes>/api/display/ws?display_ticket=<enc>`, with only that parameter, `perMessageDeflate: false`, `maxPayload` 1 MiB for the browser→Hermes direction, and no Origin, cookie or token headers.
- Backpressure: pause the reader while the peer's `bufferedAmount` is above 1 MiB, resume below 256 KiB, polling every 20 ms.
- Close mapping:
  - browser 1000/1001 → `upstream.close(1000)`;
  - any other browser close or abnormal end → `upstream.terminate()`;
  - Hermes codes and reasons forwarded with `forwardableCode`, reason capped at 120 chars;
  - upstream HTTP 403 → browser close 4403;
  - dial failure → 1013;
  - a missing ticket → 4401 without dialing.

  - `refuses the upgrade without our Host, exact Origin and session`
  - `forwards only display_ticket and sends no Origin, cookie or token upstream`
  - `turns an abnormal browser close into an upstream terminate, keeping the lease` (Review Focus 1)
  - `turns a browser 1000 or 1001 into an upstream close 1000`
  - `forwards Hermes close codes and reasons to the browser`
  - `answers 4403 for an upstream 403 and 1013 for a failed dial`
  - `pauses the reader under backpressure and resumes when drained`
  - `never logs the ticket`
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement.** **Step 4: Run** the full server suite → PASS.

### Task 3: Fail-closed `display.*` guard on `/api/ws` (server)

**Files:**
- Create: `app/server/src/hermes/display-guard.ts`
- Modify: `app/server/src/hermes/ws-proxy.ts` (inspect browser→Hermes frames), `app/server/src/main.ts` (inject `knownBots`)
- Test: `app/server/test/display-guard.test.ts`

**Interfaces:**
- Produces `checkBrowserFrame(raw: RawData, isBinary: boolean, knownBots: () => ReadonlySet<string>): { forward: true } | { forward: false; reply?: string }`.
- Behaviour:
  - parse every text frame; unparseable → reply `{jsonrpc:'2.0', id:null, error:{code:-32700}}`, not forwarded;
  - arrays → -32600;
  - binary → dropped;
  - for `method` starting `display.`:
    - refuse `display.start`, `display.install*` and `display.switchSandboxImage` (-32601);
    - require `params.profile` as a string exactly in `knownBots()` (no trimming), else -32602 with the request id;
  - other methods are forwarded unchanged.
- `knownBots` comes from the watcher's roster (`BotStateTracker` / profiles list), injected through `WsProxyDeps`.

  - `refuses display frames Hermes would mis-target` (Review Focus 3: no profile, `" crew-test"`, unknown bot, NaN, an array, a binary frame, `display.start`, `display.install`)
  - `forwards display.status/observe/lease/thumbnail/stop with a known profile unchanged`
  - `forwards non-display frames byte-for-byte`
  - `replies with the original request id`
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement.** **Step 4: Run** the full server suite → PASS.
