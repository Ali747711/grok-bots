# Crew Phase 6: Bot Sandbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A per-bot switch that runs a bot's commands, files, code and screen in Hermes's own Docker sandbox, with honest status, an image download, Reset, a roster badge, and a delete that cleans up the root-owned sandbox folders.

**Architecture:**
- Crew writes Hermes's per-bot config through the existing sparse `PUT /api/config?profile=` and keeps what it added in `ui_meta['hermes-bots'].sandbox` (CAS). Every docker call goes through one injectable runner in `sandbox/docker.ts`: fixed argv, no shell.
- `readSandbox` combines raw config (`state: off|on|partial` from a pure function), the marker and docker checks. The roster gets `BotView.sandbox` from raw config only (cached, no docker).
- Delete runs: `docker rm -f` by label → the `lstat`-guarded root cleanup helper → `profiles.delete`; any failure stops before Hermes is called.

**Tech Stack:** Server: Node 24, Hono, Zod 4, Vitest, `node:child_process` (`execFile`, `spawn`), `node:fs/promises` (`lstat`). Web: React 19, Vite 8, Tailwind v4, shadcn base-nova (Base UI), lucide-react, sonner, Vitest + Testing Library. e2e: Playwright on the VM.

**Spec:** `docs/superpowers/specs/2026-11-10-crew-phase6-bot-sandbox-design.md`. §11 rulings override earlier text; §11.6 is the latest. Facts: `docs/phase6/hermes-facts.md` ("facts §n", E1–E10). The "Plan rulings" below bind like the spec.

## Global Constraints

- **Bots:**
  - Never touch the bots `default`, `reese`, `x` or `telegram`.
  - Never change crew-test's terminal backend (it must stay `local` for the Phase 1 approval e2e). Tests may only *read* crew-test's sandbox.
  - Test bots are `e2e<digits>` only.
- **Credit:** implementers never run `@model` specs; they may only `--list` them. The controller runs `sandbox-model.spec.ts` once.
- **Services and Hermes:** implementers never restart `hermes-gateway`, `hermes-dashboard` or the `crew` service, and never edit `~/.hermes` (the source at `~/.hermes/hermes-agent` is read-only reference). Deploying to the live crew service is a **controller** step; e2e steps that need the deployed build are marked controller-run.
- **Docker:**
  - Every call goes through the `DockerRunner` of `sandbox/docker.ts`: `execFile`/`spawn` with `shell: false`, a fixed argv, `killSignal: 'SIGKILL'`.
  - Timeouts: 5000 ms for each check and `rm`; 60_000 ms for the cleanup helper; the pull has no short timeout (cap 3_600_000 ms), one at a time globally.
  - The only user input that reaches an argv is a bot name that passed `PROFILE_NAME_RE`, used as a label value. The image name comes from config and must pass `isValidImage`.
  - Unit tests use a fake runner; no real docker in unit tests (a real child process standing in for docker is fine).
- **Values:** image `nousresearch/hermes-sandbox:desktop`; `terminal.container_memory: 3072`; `terminal.docker_run_as_host_user: true`; label `hermes-profile=<bot>`; helper label `crew-cleanup=<bot>`.
- **Errors:** no HTTP body, log line or UI text carries a path or docker output. Codes: `docker_unavailable`, `image_missing` (409), `sandbox_cleanup_failed` (409), `bad_image_name` (502).
- **Project rules:** Zod at boundaries (`.strict()` bodies); files < 400 lines; functions < 50; theme tokens only (the theme-tokens scan stays green); the dark-variant trap (reuse `HideSection`'s switch classes); no `console.log`; named exports except React components; CSP unchanged (`SPA_CSP`); no new npm dependency. ## Review Focus

1. **The user's own `agent.disabled_toolsets` entries.** Hermes's `_deep_merge` replaces arrays (`hermes_cli/config.py:1373`), so a sparse `['browser']` would wipe them. Expected: Crew always writes the full list; a user's `tts` survives on and off, and a `browser` the user set before turning on survives switch-off (Task 2 tests `keeps the user's own disabled toolsets in the full list it writes, on and off` and `never removes a browser entry the user set before turning on`).
2. **Deleting a bot that was sandboxed once and later switched off.** Its config says `local`, but `sandboxes/docker` still holds root-owned mountpoints (§11.6). Expected: the helper runs because the folder exists, whatever the config says (Task 3 test `runs the helper for a bot whose config is local but whose sandboxes/docker folder exists`).
3. **A wedged Docker daemon.** A docker command that never returns. Expected: it is killed at 5 s; the status says "Docker isn't available on this computer"; turning on is refused; deleting a never-sandboxed bot still works (Task 1 `kills a command that runs past its timeout`, Task 2 `reports docker down and skips the image check when docker info times out`, Task 3 `deletes a never-sandboxed bot when Docker is missing or down`).
4. **Two Download clicks, or two tabs.** Expected: exactly one `docker pull`; both see the same progress (Task 1 `starts one docker pull for two start calls`, Task 4 `POST pull starts one pull for two requests, answers 200 when present and 409 when docker is down`, Task 6 `starts one download for two quick clicks`).
5. **A stale UI after a failed switch.** The config may be written while the marker write failed. Expected: the section re-reads and shows what Hermes holds (Task 2 `surfaces a marker write failure as not_saved after the config write`, Task 6 `re-reads the sandbox after a failed switch`).

## Plan rulings (gaps closed here)

- **R1. Switch-off** writes `terminal.backend: local`, and `agent.disabled_toolsets` only when Crew's `browser` is removed. `container_memory` and `docker_run_as_host_user` stay (harmless under `local`; rewritten on the next on). Switch-on writes `agent.disabled_toolsets` only when `browser` is missing. Fewer added keys means less comment damage (facts gotcha 23).
- **R2. Escape settings for `partial`.** §11.4 says "none of the escape settings from facts gotchas 3 and 14", so the list also covers `docker_mount_cwd_to_workspace: true`, a non-empty `docker_shared_container_key`, `browser.engine: lightpanda` and `browser.use_real_profile: true`. The reasons are fixed in Task 2.
- **R3. Delete without Docker.** When `docker info` fails, the delete stops (409) only if `sandboxes/docker` exists as a real folder. Otherwise it goes on, so a never-sandboxed bot can be deleted on a machine without Docker. When Docker answers, a failed `docker rm -f` stops the delete.
- **R4. Symlinks.** If `sandboxes` or `sandboxes/docker` is a symlink, the helper never runs and the delete goes on (Hermes's `rmtree` unlinks the link; nothing root-owned is inside the profile).
- **R5. No implicit pull.** The helper runs only after `docker image inspect` finds the image, because `docker run` would otherwise download 1.2 GB unasked (§4). Missing → 409. The proven E9 argv stays exact.
- **R6. One managed image.** Download always pulls `DEFAULT_IMAGE`. A bot whose `terminal.docker_image` names another image gets the status and the pinned-image note, but no Download button.
- **R7. Create writes the marker with the look** (one `updateBotMeta`), so a failed look still leaves `ui_meta` revision 0 and "Finish setup" keeps working.
- **R8. Pull progress.** Layers come from `<id>: Pulling fs layer|Waiting|Already exists|Pull complete` lines; bytes only when a line carries `<a>/<b>` sizes (decimal units). The output shape under the containerd snapshotter is UNVERIFIED: unknown lines are ignored, and the exit code decides success.
- **R9. Roster state** is cached per bot for 60 s and dropped after Crew's own writes (`onChanged`). Hand edits show within a minute. A failed read keeps the last known value.
- **R10. Reset needs Docker** (409 `docker_unavailable`). Removing the container at switch-off is best-effort, because the config is already `local`: a failure is logged as `{bot, kind}`.
- **R11. Check-failure reasons** in "Couldn't check the sandbox: <reason>": 503 → "Hermes is offline"; 502 `bad_image_name` → "the image name in this bot's settings isn't valid"; anything else → "Hermes didn't answer".
- **R12. Groups.** The warning shows when the bot is in at least one room of `CrewState.groups`, whether the sandbox is on or off. "What stays outside" always carries the same sentence verbatim.
- **R13. `hermesHome`** comes from `CREW_HERMES_HOME` (default `~/.hermes`). It must be absolute and contain no `:` or `,`, because it becomes a `-v` source.

**Interfaces:**
- Produces (`docker.ts`):
  ```ts
  export const DOCKER_TIMEOUT_MS = 5_000; export const CLEANUP_TIMEOUT_MS = 60_000
  export const DEFAULT_IMAGE = 'nousresearch/hermes-sandbox:desktop'
  export type DockerState = 'ok' | 'missing' | 'down'
  export interface RunResult { readonly outcome: 'ok' | 'not_found' | 'timeout' | 'exit'; readonly code: number | null; readonly stdout: string; readonly stderr: string }
  export interface DockerRunner {
    run(args: readonly string[], timeoutMs: number): Promise<RunResult>                                     // never rejects
    stream(args: readonly string[], timeoutMs: number, onLine: (line: string) => void): Promise<RunResult>  // never rejects
  }
  export function createDockerRunner(bin?: string, prefix?: readonly string[]): DockerRunner  // bin 'docker'; prefix only for tests
  export class DockerError extends Error { constructor(readonly kind: 'missing' | 'down' | 'failed') }  // message `docker ${kind}`
  export class InvalidImageError extends Error {}                                                        // message 'invalid sandbox image name'
  export interface ContainerInfo { readonly id: string; readonly running: boolean }
  export interface Docker {
    status(): Promise<DockerState>
    imagePresent(image: string): Promise<boolean>
    containers(bot: string): Promise<readonly ContainerInfo[]>
    memoryMb(id: string): Promise<number | null>
    removeContainers(bot: string): Promise<number>
    cleanupSandboxes(bot: string, sandboxesDir: string, image: string): Promise<void>
  }
  export function createDocker(runner: DockerRunner): Docker
  export function isValidImage(image: string): boolean        // /^[A-Za-z0-9][A-Za-z0-9._:/@-]{0,254}$/
  export function parseMemUsage(text: string): number | null  // '311.2MiB / 3GiB' → 311 (MiB, rounded, at least 1)
  export function cleanupArgs(bot: string, sandboxesDir: string, image: string): readonly string[]
  ```
  - `run` uses `execFile(bin, [...prefix, ...args], {timeout, killSignal: 'SIGKILL', maxBuffer: 1 MiB, shell: false})`. `ENOENT` → `not_found`; killed by the timeout → `timeout`; a non-zero exit → `exit`.
  - `stream` uses `spawn` with `shell: false` and a SIGKILL timer. It calls `onLine` for each `\n`/`\r`-split stdout line and keeps the last 64 KiB of stderr.
  - Argv (exact), 5 s each unless noted:

    | Call | Argv | Mapping |
    |---|---|---|
    | `status` | `info --format {{.ServerVersion}}` | ok + non-empty stdout → `ok`; `not_found` → `missing`; else `down` |
    | `imagePresent` | `image inspect --format {{.Id}} <image>` | ok → true; exit with `/No such image/i` → false; `not_found` → `DockerError('missing')`; else `DockerError('down')` |
    | `containers` | `ps -a --filter label=hermes-profile=<bot> --format {{.ID}} {{.State}}` | ids failing `/^[0-9a-f]{12,64}$/` are dropped; `running` = state `running` |
    | `memoryMb` | `stats --no-stream --format {{.MemUsage}} <id>` | any failure → null |
    | `removeContainers` | `containers(bot)`, then `rm -f <id…>` (skipped when none) | a failed rm → `DockerError('failed')` |
    | `cleanupSandboxes` | `cleanupArgs(...)`, 60 s | not ok → `DockerError('failed')` |

  - `cleanupArgs` returns exactly `['run','--rm','--network','none','--user','0:0','--label',`crew-cleanup=${bot}`,'--entrypoint','rm','-v',`${sandboxesDir}:/s`,image,'-rf','/s/docker']` (facts §11.2 step 4).
  - Guards before any run: `bot` must match `PROFILE_NAME_RE`, else throw `Error('bad bot name')`. `image` must pass `isValidImage`, else `InvalidImageError`. `sandboxesDir` must be absolute without `:` or `,`, else `Error`.
- Produces (`pull.ts`):
  ```ts
  export const PULL_TIMEOUT_MS = 3_600_000
  export interface PullTally { readonly layers: ReadonlyMap<string, 'pending' | 'done'>; readonly bytes: ReadonlyMap<string, { readonly done: number; readonly total: number }> }
  export const EMPTY_TALLY: PullTally
  export function parsePullLine(tally: PullTally, line: string): PullTally   // returns the same object for lines it ignores
  export interface PullProgress { readonly layersDone: number; readonly layersTotal: number; readonly bytesDone: number | null; readonly bytesTotal: number | null }
  export function progressOf(tally: PullTally): PullProgress
  export type PullError = 'no_space' | 'network' | 'failed'
  export function pullErrorOf(result: RunResult): PullError
  export interface PullState { readonly pulling: boolean; readonly progress: PullProgress | null; readonly error: PullError | null }
  export interface ImagePuller { state(): PullState; start(): 'started' | 'running' }
  export function createImagePuller(runner: DockerRunner, image?: string): ImagePuller   // stream(['pull', image], PULL_TIMEOUT_MS, …)
  export type ImageStatus = PullState & { readonly image: string; readonly docker: DockerState; readonly present: boolean }
  export function imageStatus(docker: Docker, puller: ImagePuller): Promise<ImageStatus>  // docker not ok → present false, no inspect
  ```
  - Line rule (R8): `^([0-9a-f]{12,64}): (Pulling fs layer|Waiting|Downloading|Verifying Checksum|Download complete|Extracting|Pull complete|Already exists)`, with optional `<a><unit>/<b><unit>` sizes (`B`, `kB`, `MB`, `GB`; powers of 1000). `Already exists` and `Pull complete` mark a layer done; done layers count their full size.
  - `pullErrorOf`: stderr `/no space left on device/i` → `no_space`; `/dial tcp|no such host|i\/o timeout|connection refused|TLS handshake|network is unreachable/i` → `network`; anything else, including a timeout → `failed`.
  - A failure logs `log.warn('sandbox image pull failed', {error: code})`, never stderr. The error stays in `state()` until the next `start()`.

- Produces (`sandbox.ts`):
  ```ts
  export interface SandboxDeps {
    readonly docker: Docker; readonly puller: ImagePuller; readonly hermesHome: string
    readonly groups: () => GroupsState
    readonly onChanged?: (bot: string) => void      // Task 4 wires the roster cache's invalidate
  }
  export interface SandboxView {
    readonly state: SandboxState; readonly reasons: readonly string[]; readonly image: string
    readonly docker: DockerState; readonly imagePresent: boolean
    readonly container: { readonly running: boolean; readonly memMb: number | null } | null
    readonly addedBrowserDisable: boolean
    readonly groups: readonly { readonly id: string; readonly name: string }[]
  }
  export class SandboxRefusedError extends Error { constructor(readonly code: 'docker_unavailable' | 'image_missing') }
  export function readRawConfig(deps: Pick<BotDeps, 'rest'>, name: string): Promise<Record<string, unknown>>  // GET /api/config {profile, include_defaults:'false'}
  export function writeConfig(deps: Pick<BotDeps, 'rest'>, name: string, config: Record<string, unknown>): Promise<void>  // PUT /api/config {profile} body {config}
  export function groupsWithBot(groups: GroupsState, bot: string): SandboxView['groups']
  export function readSandbox(deps: BotDeps, sb: SandboxDeps, bot: string): Promise<SandboxView>
  export function setSandbox(deps: BotDeps, sb: SandboxDeps, bot: string, on: boolean): Promise<SandboxView>
  export function resetSandbox(deps: BotDeps, sb: SandboxDeps, bot: string): Promise<SandboxView>
  ```
  - `readSandbox`:
    - reads raw config, the marker and `docker.status()` in parallel;
    - throws `InvalidImageError` before any image call when `effectiveImage` fails `isValidImage`;
    - only when docker is `ok`, calls `imagePresent` and `containers`, then `memoryMb` for the first running one;
    - a `DockerError` from those makes `docker: 'down'`;
    - `container`: `null` with no containers, else `{running, memMb}`.
  - `setSandbox` runs under `withBotLock(bot)`:
    1. Read raw config and marker.
    2. For on: `status !== 'ok'` → `SandboxRefusedError('docker_unavailable')`; image absent → `'image_missing'`. Nothing is written on refusal.
    3. Write `patch.config` (one PUT).
    4. `updateBotMeta(rpc, bot, {sandbox: patch.marker})`; a `BotMetaWriteError` → `NotSavedError('ui_meta')`.
    5. For off: `removeContainers(bot)`, best-effort (R10).
    6. `sb.onChanged?.(bot)`, `refreshQuietly`, then return `readSandbox`.
  - `resetSandbox` (locked): `status !== 'ok'` → `SandboxRefusedError('docker_unavailable')`. Then `removeContainers(bot)` (a `DockerError` → `'docker_unavailable'`), `onChanged`, return `readSandbox`.
